# 产品解决方案页布局优化设计

## 背景

当前“项目管理”页把产品列表和解决方案配置堆在同一列里，解决方案编辑依赖弹窗和大段 JSON 输入，正式环境维护时定位当前产品、切换解决方案、确认选中态都不够直观。

## 目标

- 把页面改成明显的左右结构。
- 左侧展示产品导航，并提供清晰的选中效果。
- 右侧展示当前产品详情、解决方案列表和解决方案配置区。
- 保持现有后端接口和数据结构不变，优先完成交互和信息层级优化。

## 方案

### 1. 页面主布局

- 左侧固定为产品列表导航区。
- 右侧拆成“当前产品信息”和“解决方案配置”两块。
- 解决方案配置区再拆为“解决方案列表”和“详情/编辑区”。

### 2. 选中态

- 产品列表卡片增加明显的背景、边框和阴影变化。
- 解决方案列表同样支持选中态，避免管理员在多个方案间切换时迷失。
- 当产品切换后，如果当前已选解决方案不存在，则自动回退到该产品的第一个解决方案。

### 3. 编辑交互

- 产品新增/编辑继续沿用弹窗，减少改动范围。
- 解决方案新增/编辑改为右侧内嵌面板，不再弹窗遮挡上下文。
- `build_profile` 和 `roots` 仍保留 JSON 编辑方式，但通过更清晰的分区和说明文案提升可读性。

### 4. 风险控制

- 不修改后端接口。
- 不调整解决方案的数据结构。
- 不引入“全部产品批量执行”相关逻辑，避免本轮范围扩大。

## 验证点

- 首次进入页面时，自动选中第一个产品。
- 切换产品时，右侧内容同步刷新。
- 当前产品没有解决方案时，右侧显示明确空状态。
- 选中某个解决方案后，可在右侧查看和编辑对应配置。
